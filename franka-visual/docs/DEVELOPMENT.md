# 开发过程与验收记录

这是基于代码、时间戳、测试与产物整理的工程记录，不是逐字聊天备份。完整草稿、修订脚本、失败测试日志、原始训练/评测记录和私人交接仅在本机留存。

## 决策与实现顺序

1. 只读核对旧低维实验、数据SHA、源码与1800条记录，确认旧测试已消耗。先完成项目，再另行学习；不以工程完成替代个人能力验收。
2. 固定8小时机器预算、视觉BC/视觉扩散、各三种子10000更新，预检不满足就停止，不削减种子或为赢而调参。
3. 用12条旧验证失败冻结几何现象分类，再恢复61条旧测试失败与12条成功参照。接近、横移和闭爪指令只作观测证据，不冒充接触/抓取因果。
4. 恢复200条演示XML/状态生成9666帧RGB，保留官方180/20划分。逐帧对齐、数值观测、图像方向与状态不变检查通过；物体真值不进入派生策略输入。
5. GPU/EGL在宿主机可用；沙箱的驱动查询限制不等于驱动故障。沿用独立Python3.11环境，未安装依赖或更改实验室控制电脑。
6. 预检每方法60临时更新、checkpoint/EMA重载、旧task17满400步；batch32通过，BC峰值约0.37GiB、扩散约1.99GiB。保守估计含25%余量7.83小时，足以进入原定正式预算。
7. 全部训练结束后验证30候选共600回放；成功数优先，同分更早。BC选8000/8000/10000，扩散10000/8000/10000。六模型/源码/数据身份冻结后才建立最终任务。
8. 最终100个共同物理任务一次评测，BC300/扩散900回放，异常0。模型和EMA推理前后未变。1800条记录独立算术与文件审计通过，11项原验收回归测试通过。
9. 视频仅恢复保存状态，不增加策略回放。新旧物理任务隔离、原数据和源码SHA、bootstrap算术均复核；原实验、失败和checkpoint保留。

## 开发中修复并留证的问题

正式冻结前修复：测试误用Config属性访问、SequenceDataset参数/动作配置不匹配；机械字符串替换导致的噪声offset错误；入口拒绝覆盖时异常回执可能写入既有目录的问题；补齐机器预算保护、规划延迟、图像审阅记录及逐条审计。相关失败测试和修订草稿本地保留，未混入正式成绩。
