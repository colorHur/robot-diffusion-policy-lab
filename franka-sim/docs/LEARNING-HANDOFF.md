## 后续教学方式

每次按“解释问题 → 学习者先预测 → 亲手运行 → 对照源码 → 闭卷复述 → 小改动验证”推进。一次只处理一个关键概念，不用连续堆术语代替理解。不要替学习者回答验收题，不以脚本跑通证明学会。先阅读本记录、RESULTS和INTERVIEW-NOTES；沿用现有环境，先用已有轨迹与模型，不默认重新训练整套实验。

逐节记录：实际命令、预测与观察差异、本人解释、未懂的问题、代码改动、验收依据和下一步。只有用户亲自展示的能力才能进入“已掌握”，未出现的回答始终写“待验收”。

## 项目故事骨架（事实与假设分开）

问题：机器人模仿学习策略的离线损失不能保证闭环有效，如何在有限显存和时间下建立可信的比较？

实施：使用官方Panda Lift低维演示；隔离180/20条数据；固定三训练种子、batch32与每模型10000更新；用独立验证任务选模、冻结模型身份；复用100个相同初始物理任务，扩散增加固定噪声重复；记录成本、视频和可审计轨迹。

结果：BC均值89.67%、扩散96.67%，固定模型条件下差7个百分点、配对任务区间3至11.22个百分点。结果是完整方法配置的比较；参数量、时域与重规划频率不同，不能声称仅由扩散机制导致提升。真实机器人部署尚未完成。

深度来自能解释设计选择、失败与代价，而不是高分本身。应能回答：为什么100个任务不是1200个独立样本？为什么valid演示与验证仿真任务不同？为什么不在训练中rollout？EMA如何检查？为什么相同种子不足以保证公平？成功定义为何不代表稳定抓取？何时应优先用简单BC？
