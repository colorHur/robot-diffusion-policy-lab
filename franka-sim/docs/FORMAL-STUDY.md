# Panda Lift 正式低维对照：运行与解释

本轮问题：在固定演示数据、训练种子与更新预算下，两套官方方法在相同初始任务上的闭环表现、推理和训练成本如何？不是单独隔离扩散机制的因果研究，也不是已完成真机部署。

## 已固定设置

- 官方200轨迹中train180/valid20不相交；BC单帧单动作，扩散To2/T16/Ta8。
- BC默认1024×2 MLP；DP默认U-Net256/512/1024＋EMA，DDIM10，两个方法共同batch32。
- 种子7/17/27，各10000更新，每2000保存；新模型不复用冒烟checkpoint。
- 验证任务20000–20019，采样offset0，成功数优先、同分更早step。
- 所有6模型选择冻结并记录SHA后才创建test30000–30099；BC每模型100回放，DP每模型100×3噪声回放，共1200回放但仅100独立测试任务。
- 不以训练/验证loss跨方法排名。噪声先在训练seed内平均；按任务配对bootstrap区间仅对固定模型/噪声有效。
- 从首次资源预检开始总8小时上限；按预检加入25%余量估计6.17小时。实际时间/失败以status和日志为准。

预检验证1200个实际dataset边界样本，检查upstream把action转float32而保持原obs精度的行为。验证数据复用训练归一化统计，避免内部dataset为valid重新估计统计。初次HDF5 SWMR/单数据集返回类型/float32审计错误均已保留，未启动正式训练时修复；所有重试沿用首次截止时间。

## 入口

项目根目录：`franka-sim`。

```bash
# 以下两个命令仅示例；已有目录禁止覆盖，不要重复启动同一GPU任务。
./sim preflight --out runs/NEW-PREFLIGHT
./sim study --preflight runs/NEW-PREFLIGHT --out runs/NEW-STUDY
# 当前轮验收（完成后可复核）
./sim audit --out runs/panda-study-20261020
```

查看`runs/panda-study-20261020/status.json`。训练日志为`train-bc-7.log`等，验证和测试分别保存在独立目录；原始动作/物理状态每条存档。status只有在训练、选择冻结、测试、视频生成与独立审计完成后才会标complete。incomplete必须保留，不自动resume或改超参刷分。

## 成果如何讲清楚

先解释数据/观察/动作，再解释两种方法差异，最后看固定闭环结果及成本。成功和失败视频由实际保存的策略轨迹重放，不增加策略回放次数；元数据绑定对应任务/训练seed/噪声/模型SHA。失败结果同样交付，不能只展示成功。

正式结果只引用当前summary、audit和状态，不引用旧冒烟的2/4作为基准。训练成功也不等于学习者已掌握；后续应由本人解释To/T/Ta、DDPM/DDIM、EMA、数据切分与模型选择，并独立复跑小任务。

讲解与本人学习验收见[讲解提纲](INTERVIEW-NOTES.md)。时序对齐特别注意：官方DP执行切片从To-1开始，T16是训练动作片段长度，不应把原始17项dataset样本全部当作未来执行动作。
